# 09｜原生 URL 短音檔測試方案

狀態：規劃中，尚未播放。這項測試會讓音箱實際發聲；開始執行前須另行確認測試時機與音量環境。

## 目的

確認 HD 原生播放器能否從受控的本地 HTTP 來源播放短音檔，以及能否停止並回到測試前狀態。這是播放器路徑測試，不涉及 HD Client 的錄音、TTS、ALSA 或驅動修改。

## 執行前準備

1. 從 HD 自己的備份與只讀介面確認實際的播放、停止和狀態查詢方法。只有「URL 播放介面存在」的盤點結果，不能當成參數和停止語意已確認。若無法確認可靠的停止方法，暫停測試。
2. 準備一段約 3 秒、峰值受限、無人聲的測試 WAV；先在電腦試聽，確認沒有爆音。播放格式需依 HD 原生播放器已知支援範圍決定，不猜測格式。
3. 由本地臨時 HTTP Server 提供單一音檔，Server 僅綁 loopback；使用已驗證可用的 SSH 反向轉送讓 HD 連線到該服務。避免把測試服務公開到 LAN 或網際網路。
4. 不安裝或啟動握手 Client；使用既有 SSH 工作階段執行經核對的單次播放器命令。測試前讀取播放狀態與目前音量，僅記錄、不調整。

## 單次測試順序

1. 讀取並記下播放狀態；確認沒有需要保留的音樂或其他播放工作。
2. 發出一次已核對的 URL 播放呼叫。只播放單一短音檔，不設定循環、不重試、不建立背景任務。
3. 觀察實際聲音，並以只讀狀態查詢確認播放器回應。若無聲、失真、音量異常或狀態不明，立即用已驗證的停止方法中止，不再重試。
4. 音檔播完後確認播放器停止或回到預期狀態；若測試前原本閒置，不應留下播放工作。若測試前正在播放內容，先不要開始測試，避免打斷使用者播放。
5. 關閉 HTTP Server 與 SSH 轉送，再查一次狀態。確認沒有測試程序、播放工作或臨時檔殘留。

## 不在本方案內

不改音量、播放器設定、ALSA、DSP、開機項目或分區；不錄音、不傳送 TTS、不測長音檔／串流、不接 NAS 長期服務。若需要上述任何項目，另立測試並先說明影響。

## 記錄與驗收

記錄日期、韌體版本、是否使用握手 Client（本方案預期為否）、音檔格式與長度、播放器呼叫結果、播放／停止狀態、是否聽到聲音、清理結果。報告不保存裝置唯一識別碼、私人位址、音檔 URL 或 SSH 資訊。

成功條件：音箱只播放一次短音檔，停止／自然結束可確認，測試後無殘留工作，既有設定保持原樣。這只證明該台 HD 在該次測試中的原生播放路徑，不代表所有格式或遠端服務都相容。
